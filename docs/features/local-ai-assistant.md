# المساعد الذكي المحلي — المرحلة الأولى

## الهدف

تجهيز محرك أوامر مالي محلي يعمل على الهاتف دون الاعتماد على Gemma أو اتصال بالشبكة لتنفيذ الأوامر المالية المدعومة. هذه المرحلة تركز على تنفيذ عمليات التطبيق الفعلية، لا على محاكاة محادثة نموذج لغوي عام.

## مسار التشغيل

1. يستقبل المحرك النص المكتوب أو النص الناتج من إدخال الميكروفون.
2. يطبّع الحروف العربية والهمزات والتشكيل، والأرقام العربية/الفارسية، وصيغ الأعداد الشائعة، وأسماء الأشهر.
3. يستخرج النية والحقول اللازمة: القسم، نوع العملية، التصنيف، الطرف المقابل، المبلغ، الشهر/التاريخ، والملاحظة.
4. يطابق النتيجة مع اسم عملية معتمد في `ActionRegistry`. لا يُسمح بتشغيل اسم عملية غير مسجل أو معاملات من نوع غير صحيح.
5. تنفذ عمليات الكتابة عبر مستودعات العمل والمنزل والفواتير والديون والتصنيفات؛ وبذلك تظل قواعد الرصيد والدفعات والقيود نفسها التي تستخدمها الواجهات اليدوية نافذة.
6. تعرض شاشة المساعد معاينة العملية باستخدام `FinancialRecordCard` قبل التنفيذ. لا تُنفّذ عملية كتابة إلا بعد ضغط المستخدم على التأكيد. يمكن إلغاء المعاينة، وتتوفر عملية تراجع عند دعمها من الإجراء.

## العمليات المدعومة في المحرك المحلي

| القسم | الأوامر |
|---|---|
| العمل | إضافة راتب، إضافة سلفة، تسجيل دفعة من الراتب، عرض السجلات، عرض الباقي، وقراءة مجموع شهر محدد |
| تحويلات المنزل | إضافة تحويل من العمل إلى المنزل، عرض التحويلات، وحذف تحويل باستخدام معرّفه |
| المنزل / المصروفات | إضافة مصروف بتصنيف جاهز أو مخصص، التاريخ والملاحظة، عرض المصروفات لشهر أو كل السجل، حذف سجل بمعرّفه |
| التصنيفات | عرض التصنيفات، إنشاء تصنيف مخصص، وحذف تصنيف مخصص غير مستخدم؛ التصنيفات الافتراضية محمية |
| الفواتير والإيجارات | إضافة فاتورة أو إيجار شهري، عرض الفواتير، تسجيل دفعة باسم الفاتورة المطابق أو معرّفها، عرض سجل الدفعات، وحذف فاتورة لا تملك تاريخ دفعات |
| الديون | إنشاء دين لك (دائن) أو عليك (مدين)، عرض الديون، تسجيل دفعة باستخدام اسم الطرف/اتجاه الدين أو المعرّف، عرض سجل الدفعات، وحذف دين لا يملك تاريخ دفعات |
| الملخص والتنقل | قراءة ملخص الشهر، إجماليات الأقسام، رصيد العمل، والتنقل إلى الشاشة المطلوبة |

تدعم أوامر الإضافة التاريخ الصريح بصيغ ISO أو يوم/شهر/سنة، وتدعم إضافة ملاحظة عند كتابتها. عند عدم ذكر يوم، يُستخدم تاريخ اليوم داخل الشهر المطلوب كقيمة ظاهرة في بطاقة المراجعة. وإذا كان حقل أساسي مفقوداً، يسأل المساعد بدلاً من اختراعه.

## سلامة البيانات

- تستخدم العمليات أسماء الأفعال والمعاملات المعرّفة في `ActionRegistry` فقط.
- تمر الإضافة والتعديل والدفعات بقيود المستودعات الحالية؛ لا يوجد إدخال SQL مباشر من المحرك إلى جداول المعاملات.
- يرفض سجل الأوامر المعاملات ذات النوع أو القيمة غير الصحيحة.
- لا يُحذف دين أو فاتورة لهما تاريخ دفعات من مسار الحذف العادي.
- عند تطابق اسم فاتورة أو طرف دين مع أكثر من سجل، لا يختار المحرك سجلاً عشوائياً؛ يجب تحديد المعرّف أو إزالة الالتباس.
- لا يتم الحفظ قبل موافقة المستخدم على بطاقة المعاينة.

## حدود المرحلة الأولى

هذا محرك قواعد/أوامر محلي، وليس نموذجاً توليدياً عاماً. يفهم الصيغ العربية والإنجليزية والمرادفات المدرجة في المحلل، لكنه قد يطلب إعادة صياغة الطلب إذا خرج عن تلك الصيغ. ينفذ إجراءً مالياً واحداً في كل مرة حتى تكون معاينة كل عملية وموافقتها واضحة.

معالجة الصور والملفات الصوتية كمرفقات ليست ضمن المحرك المحلي؛ تظهر رسالة تفيد بأن هذه الوظيفة تتطلب Gemma. هذا لا يمنع إدخال الصوت عبر زر الميكروفون وتحويل الكلام إلى نص قبل الإرسال عندما يدعم الجهاز التعرف المحلي.

## المرحلة الثانية — Gemma

تُستكمل لاحقاً، بعد تثبيت واختبار محرك المرحلة الأولى، وتشمل ربط `GemmaAssistantEngine` بمخطط العمليات الفعلي، وحقن قائمة التصنيفات الحقيقية، والتحقق من مخرجات النموذج قبل تمريرها إلى `ActionRegistry`. يبقى المحرك المحلي هو المسار الاحتياطي، ولا ينبغي أن تصبح سلامة تنفيذ العمليات أو استخدام التطبيق معتمدة على وجود النموذج.
