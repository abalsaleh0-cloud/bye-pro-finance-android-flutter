# BYE PRO Finance 1.1.101 — Gemma runtime diagnostics and assistant identity

**Version:** 1.1.101+202  
**Platform:** Android Production / Release  
**Scope:** Android application only. The web source repository is unchanged.

## Gemma identity in chat
- Label each assistant response with the engine that actually produced it: **Gemma المحلي**, **المساعد المحلي**, or **المساعد المحلي (بعد تعذّر Gemma)**.
- Persist the source label with the chat message so it remains visible after opening saved conversations.
- Do not label a local fallback response as Gemma merely because Gemma is enabled.

## Gemma runtime verification in Settings
- Separate model-file integrity status from actual inference status.
- Add a manual on-device inference test with explicit states: not tested, testing, succeeded, and failed.
- Store the last runtime result, reason, and timestamp in app settings so it remains visible after restarting the app.
- Mark success only after Gemma returns a real text or structured action response.
- On runtime failure, keep the verified model file installed and allow an in-place retry; do not ask the user to delete or download the multi-gigabyte model again.
- Rename the file status to clarify that file verification alone does not prove runtime execution.

## Startup and welcome screen
- Returning users are routed to the dashboard after the saved first-launch flag is restored.
- During that brief restore check, show only a neutral loading indicator rather than briefly displaying the first-launch welcome content.
- Keep the welcome screen for genuine first launches.

## Monthly bills and rent
- Refresh bills and bill-payment projections immediately after assistant saves, deletes, or records a payment, and after undo.
- Improve Arabic parsing for recurring bills, subscriptions, and monthly rent.
- Keep explicit confirmation before any financial write.

## Appearance and launcher
- Fresh installs follow Android System appearance while retaining explicit saved Light/Dark preferences.
- Reconcile the official light/dark launcher aliases after app updates and app background transitions.

## Preservation and verification
- No package ID, production signing key, existing app data, or Gemma model file replacement is included.
- The web source repository is unchanged.
- Automated Flutter analysis, tests, and a signed Production build are required before release.
- Final Gemma inference, launcher icon, and startup behavior still need confirmation on the user's handset.
