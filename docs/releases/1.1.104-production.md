# BYE PRO Finance 1.1.104 — Salary writes and historical record lookup

**Version:** 1.1.104+205  
**Platform:** Android Production / Release  
**Scope:** Android application only. The web source repository is unchanged.

## Work salary writes
- Never accept a free-form Gemma sentence as proof that a salary or other write succeeded. Route non-tool write responses and unnecessary write clarifications through the deterministic local rule engine so the app produces a validated command and asks the user for confirmation.
- For new work records, remove model-invented IDs unless the user explicitly supplied a record identifier and asked to edit.
- For salary creation, extract amount, month/relative month, salary kind, explicit date, and note from the user's actual text. Do not allow a generated date to conflict with the requested allocation month.
- Refresh the work records provider after save or delete, so the new salary is shown in the Work section.

## Historical salary lookup
- Recognize questions such as “Where did you add 1500?” in the recent conversation context.
- Search work records across all months by exact amount and record kind, rather than defaulting to the currently selected month.
- Return the matching salary record's month, date, and note.

## Preservation
- Android repository only; web source repository untouched.
- Keep the exact installed `gemma-4-E2B-it.litertlm` file and its existing SHA-256 verification.
- No model deletion, replacement, or download.
- No app ID, production signing key, or database schema changes.

## Verification
- Flutter analysis and test suite.
- Regression tests for a false Gemma “saved” answer, redundant “which month?” clarification, fabricated record ID, cross-month amount lookup, and actual database save/read.

- Final inference still requires an on-device run; CI cannot perform inference on the user's handset.
