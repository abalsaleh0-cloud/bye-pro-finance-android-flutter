# BYE PRO Finance 1.1.105 — Gemma write and history safeguards

**Version:** 1.1.105+206  
**Platform:** Android Production / Release  
**Scope:** Android application only. The web source repository is unchanged.

## Gemma write safeguards
- Treat every write as successful only after an approved, repository-backed action runs.
- Route free-form success claims and redundant write clarifications to the deterministic local parser, which validates the required fields and asks for confirmation.
- Reject model-generated work-record IDs for new salary entries.
- Reject work-record edit commands that do not include a record identifier explicitly supplied by the user.
- Recognize write intent consistently across salary, payment, debt, transfer, household expense, and bill commands.

## Historical work lookup
- Search across all months by exact amount and record kind.
- Remove model-inferred month filters from historical lookup requests.
- Use the conversation history to recognize a follow-up such as “Where did you add 1500?” as a salary-record lookup.
- Display the matched record's type, amount, month, date, and note.

## Preservation
- Android repository only; the web source repository remains untouched.
- Keep the installed `gemma-4-E2B-it.litertlm` model and its SHA-256 verification unchanged.
- No app ID, database schema, or production signing key changes.
- No uninstall, data clear, or model deletion/replacement.

## Regression coverage
- Gemma cannot claim a write succeeded without an action.
- Salary 1500 for last month produces the actual salary command with the right month and note.
- New salary creation discards fabricated record IDs.
- Edit without an explicit record ID is rejected safely.
- Historical salary search ignores model-inferred current-month filters and searches all months.
- Repository save/read confirms amount 1500 is found in its original month.

Final inference on the handset still requires an on-device check; a successful build alone does not prove the local model is running correctly.
